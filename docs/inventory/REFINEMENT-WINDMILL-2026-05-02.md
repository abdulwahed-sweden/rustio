# RustIO admin — Windmill-style refinement plan

Survey + principle audit + proposed commits. **No code edits in this
file.** This is the pre-implementation review document; awaiting
authorization before any work begins.

---

## Architecture context (read first)

Three CSS surfaces hold the admin's design language:

1. **`tailwind.config.js`** (workspace root, 159 LOC) — palette source.
   Defines `rust.*`, `teal: "#338899"`, semantic `accent` token, and
   the `boxShadow` ramp. Utility classes `text-rust` / `bg-rust` /
   `bg-rust/5` resolve through this file.
2. **`rustio-core/assets/css/input.css`** (317 LOC) — Tailwind input.
   `@layer base` defines `--ds-color-*` tokens for `:root`, `.dark`,
   and `.theme-brand`/`.theme-rust`. `@layer components` holds the
   surviving legacy classes (`.results`, `.user-row`, `.actions`,
   `.badge-success/-warning/-danger/-neutral`, `.errornote`,
   `.messagelist`, `.empty-list`, `.code-pill`, `.required`,
   `.breadcrumbs`, `.checkbox-list`, `.cascade-list`, `.btn-*:disabled`).
3. **`rustio-core/assets/templates/admin/base.html`** lines 13–1485
   inline `<style>` block — the **single source of truth for v14
   component visuals**. 1472 lines of CSS in 5 sections (§1 Tokens,
   §2 Reset, §3 Layout shell, §4 Components, §5 Utilities, §10b
   splitview/tabs/timeline/show-grid/stat-strip).

There is also `rustio-core/assets/static/css/rustio.css` (public-site
stylesheet, served at `/static/rustio.css`, used by
`templates/base.html` non-admin shell) — it carries its own
`--accent: #B84318` token.

The compiled output `rustio-core/assets/static/css/admin.css` is
generated by `make css` (npm run css → `npx tailwindcss -i input.css
-o admin.css --minify`). It is NOT a source — every edit goes into
`input.css` or the inline block in `base.html`, then `make css` is run.

`make css-check` (pre-commit gate) runs the build into `/tmp` and
diffs it against the committed `admin.css`. Any token/utility
change in `input.css` or `tailwind.config.js` requires `make css` to
land alongside.

### Key insight: emerald is currently aliased to rust

`base.html` §1.5 (lines 144–150) deliberately aliases
`--emerald-50`…`--emerald-800` → `var(--rio-accent)` (rust). Every
`var(--emerald-600)` reference in the §10b splitview/tabs/timeline
rules **already renders rust** through this alias — the literal
"emerald" identifier is naming-only, not a residual emerald color.
The aliases are a verbatim port of the original Tailwind UI authoring.

Migration approach is therefore: **rename `--emerald-*` →
`--brand-*`**, drop the rust hex, point `--brand-*` at the new teal
palette. Same alias mechanism, different anchor color.
