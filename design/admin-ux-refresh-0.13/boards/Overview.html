Overview

The first screen after sign-in. Its job is to answer “what is in this workspace and where do I go next” in one glance — then get out of the way.

A

Purpose

An operator lands here to choose a model to work in. That is the primary task and nothing should compete with it. The secondary task is orientation: how much data is here, and has anything changed recently.

C · D · F

Components and proposals

Drop the “featured” stat card

The largest count currently takes a blue fill. Magnitude is not priority; the emphasis draws the eye to whichever table happens to be biggest. All model cards read the same.

Visual / UX only

Fixed column count for the model grid

repeat(auto-fit, minmax(200px, 1fr)) produces a ragged final row on wide screens.

Visual / UX only

Stat number loses the inherited link underline

The card is an <a>; the underline currently leaks onto the 33px number.

Visual / UX only

Recent activity panel

Three to five most recent audit entries, each linking to its record, with “View all activity” to /admin/actions. The audit log, its query and that page already exist; this needs the latest N entries in the dashboard context. No new table, no new permission.

Backend wiring

Per-card “New record” shortcut

A small secondary action revealed on hover/focus targeting /admin/<model>/new, hidden without create permission. Needs per-model permission in the dashboard context and a resolution of the nested-interactive question inside a card that is itself a link.

H

Visual acceptance

  • No stat card is visually emphasised over another.
  • Every row of the model grid is full; no orphan card on the last row at 1440 or 1920.
  • Record counts are not underlined.
  • Main uses the wide measure — no 1120px island inside a 1920px viewport.
  • Hero, model grid and activity panel are three clearly separated blocks, spaced only on the 4–32 scale.
  • At 390 the page scrolls vertically only.
